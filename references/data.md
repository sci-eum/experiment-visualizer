# 데이터 형식 (`EXPERIMENT`)

SKILL.md 5장에서 연다. 데이터는 JSON으로 쓰고 `python scripts/check_data.py experiment.json`으로 검사한다. 부품(`t`)과 속성은 `references/parts.md`에 있는 것만 쓴다.

## 전체 예시

`title`과 `steps`만 필수이고, 나머지는 원문에 있을 때 쓴다.

```json
{
  "title": "물의 끓는점 측정하기",
  "subject": "중학교 과학", "unit": "물질의 상태 변화", "duration": "45분", "group": "4인 1모둠",
  "goal": "물을 가열하면서 온도 변화를 측정하여 **끓는점**을 알아본다.",
  "materials": [
    { "name": "비커 (250 mL)", "qty": "1개", "icon": { "t": "beaker", "vol": "250 mL" } },
    { "name": "온도계", "qty": "1개" }
  ],
  "safety": ["가열 중인 비커는 맨손으로 만지지 않는다."],
  "tips": ["모둠원끼리 역할(가열, 온도 읽기, 기록)을 미리 나눠요."],
  "cover": { "from": 1 },
  "steps": [
    {
      "id": "heat",
      "title": "가열하며 온도 재기",
      "text": "알코올램프에 불을 붙이고 **1분마다** 온도를 기록한다.",
      "time": "약 15분",
      "point": "물이 끓기 시작한 뒤에도 측정을 멈추지 않아요.",
      "observe": "온도가 어떻게 변하는지 기록해요.",
      "tip": ["온도계 눈금은 눈높이에서 읽어요."],
      "warn": "온도계 끝이 비커 바닥에 닿지 않게 해요.",
      "origin": { "where": "2쪽 실험 과정 ③", "quote": "비커에 물 100 mL를 넣고 약 15분 동안 알코올램프로 가열하면서 1분마다 온도를 측정하여 기록한다.", "check": "ok", "added": ["tip"] },
      "scene": [
        { "t": "stand", "hold": "th" },
        { "t": "tripod", "id": "tr", "x": 280 },
        { "t": "lamp" },
        { "t": "beaker", "id": "b", "on": "tr", "vol": "250 mL", "amount": "100 mL", "bubbles": 6, "steam": true },
        { "t": "thermometer", "id": "th", "in": "b", "reading": "100 ℃" },
        { "t": "stopwatch", "x": 420, "y": 70, "time": "1분마다" }
      ]
    }
  ],
  "results": {
    "expect": "물이 끓기 시작하면 온도가 일정하게 유지된다.",
    "table": { "id": "temp", "title": "온도 기록표", "head": ["시간(분)", "0", "1", "2"], "rows": [["온도(℃)", "", "", ""]] },
    "questions": [{ "id": "why-flat", "text": "물이 끓는 동안 온도가 일정한 까닭은?" }]
  },
  "source": "2학년 과학 실험지 3번",
  "notes": "실험실 사정에 따라 가스버너를 써도 된다고 원문에 적혀 있음"
}
```

- 글자 안에서 `**굵게**`와 줄바꿈(`\n`)을 쓸 수 있다.
- `"_demo": true` 같은 템플릿 예시 값은 남기지 않는다.

## 최상위 항목

| 항목 | 뜻 |
|---|---|
| `title` | 실험 제목 (필수). 학생 답이 이 제목으로 저장되니 함부로 바꾸지 않는다. |
| `subject` `unit` `duration` `group` | 과목, 단원, 걸리는 시간, 모둠 (머리 칩) |
| `goal` | 목표 |
| `materials` | 준비물 `{ name, qty, icon, info }`. `info`는 준비물을 눌렀을 때 보이는 원문 설명 (아래 '부품 눌러 알아보기'). `icon`은 부품 이름이나 부품 객체. 생략하면 이름으로 짐작한다 ("분별 깔때기" → 분별 깔때기 그림). 용량이 있으면 `{ "t": "beaker", "vol": "250 mL" }`. 과정에만 나오는 기구는 `qty`를 `"과정에 사용"`. 맞는 부품이 없으면 `{ "t": "generic", "text": "pH" }`(첫 글자 상자). 이름 짐작이 다른 기구 그림이 되면 검사기가 알려 준다. |
| `safety` | 전체 안전 수칙 (배열) |
| `tips` | "실험 전에 알아 두기" 칸 (전체 팁·강조) |
| `cover` | 표지 장면. 보통 대표 단계를 이어받는다 `{ "from": 7 }` |
| `steps` | 단계 배열 (필수) |
| `results` | 결과 정리 (아래) |
| `source` | 원문 이름 (바닥글에 "원문: …"). 있으면 검사기가 단계마다 `origin`을 요구한다. |
| `notes` | 교사용 메모 (바닥글). **판독이 불확실한 수치는 여기가 아니라 그 단계의 `origin`에** `check: "unsure"`로 적는다. |
| `id` | 같은 제목의 다른 실험을 같은 기기에서 쓸 때 학생 답 저장을 구분한다. |

## 단계 항목

| 항목 | 뜻 |
|---|---|
| `title` | 단계 제목. 나눈 단계는 원문 번호를 남긴다 (`"3-1. 지시약 넣기"`) |
| `text` | 설명 (원문을 쉽게 다듬은 문장) |
| `scene` | 장면 (부품 배열, 또는 이어받기 객체) |
| `point` `observe` `tip` `warn` | 상자: 강조 · 관찰 · 팁 · 주의. 글자 하나 또는 배열 |
| `predict` `reveal` | 예상 칸(적는 예상·고르는 예상) · 결과 보기 (수업 기능) |
| `time` `timer` | 시간 표시와 타이머 (수업 기능) |
| `origin` | 원문 대응 기록 (아래) |
| `id` | 단계 고정 이름. 예상 칸의 학생 답이 이 이름으로 저장된다. |
| `section` `no` | 소제목(바뀌는 곳마다 나온다), 번호 자리에 쓸 글자 |
| `bench` | `false`면 실험대 바닥을 그리지 않는다 (회로도·그래프만 있는 장면) |
| `motion` | `false`면 이 단계의 움직이는 시연을 하지 않는다 (아래 '움직이는 시연') |
| `sketch` | 그 단계에서 관찰한 모습을 그리는 **그림 칸** (아래 '그림 칸') |

## 원문 대응 기록 (`origin`)

단계마다 원문 어디에서 왔는지 남긴다. 화면에서는 바닥글의 **원문 대조 보기**를 눌러야 보이고, 교사용 인쇄에는 늘 나오며, 학생용 인쇄에는 빠진다.

```json
{ "origin": { "where": "탐구 과정 2", "quote": "눈금실린더로 식초를 5 mL씩 재어 시험관에 넣는다.", "check": "ok", "added": ["tip", "predict"] } }
```

| 항목 | 뜻 |
|---|---|
| `where` | 원문 위치 (쪽, 과정 번호, 표 이름). 쪽은 원문에 인쇄된 쪽, 인쇄된 번호가 없으면 'PDF 3쪽' |
| `quote` | 근거 문장. 원문 그대로 (길면 핵심 구절만) |
| `check` | `"ok"`(원문과 맞춰 봄) 또는 `"unsure"`(판독 불확실) |
| `unsure` | 불확실한 내용 (`"50 mL인지 30 mL인지 흐림"`). 화면에 노란 "원문 확인 필요" 표시가 늘 보인다. |
| `added` | 원문에 없이 더한 항목 이름: `tip` `warn` `point` `predict` `answer` `observe` `reveal` `scene` `text` `time` `info` (예: 사용자가 준 팁 → `"tip"`, 사용자가 알려 준 예상의 정답 → `"answer"`, 사용자가 준 기구 설명 → `"info"`) |

- 양·농도·온도·시간을 확실히 읽지 못했으면 **만들기 전에 사용자에게 확인**한다 (SKILL.md 0장 멈춤 조건). 확인 없이 진행하라고 했을 때만 `"check": "unsure"`로 남긴다.
- 원문이 없는 자료(예시 모음 등)는 `source`·`origin`을 쓰지 않는다.

### 원문 숫자 대조

검사기는 단계의 제목·설명(`text`)·시간(`time`)과, 그 단계가 직접 쓴 장면의 넣은 양(`amount`)·이름표(`label`)·표시 글(`text`)에 나온 **단위 붙은 수치**(mL·L·g·℃·분·초·%·M·방울·cm·V …)가 근거 문장에 있는지 본다. 단위가 달라도 값이 같으면 같다고 본다 (`1 L` = `1,000 mL`, `30 °C` = `30 ℃`). 같은 단계 근거 문장 말고도 앞 단계 근거 문장과 준비물에 있는 수치는 근거로 친다.

- 없으면 '확인'으로 알린다: `설명의 '10 mL'가 원문 근거 문장에 없어요 (근거 문장에는 5 mL)`.
- 그러니 **근거 문장에는 그 단계의 수치가 든 구절을 빠뜨리지 않는다.**
- **표에서 옮긴 단계**는 근거 문장에 머리 줄을 함께 적는다: `"[표] 단계 / 온도 (°C) / 시간(sec): Denaturation 95 / 20, Extension 72 / 40"`. 근거 문장에 숫자 없이 적힌 단위(괄호 안 `(°C)` `(sec)` `(초)` `(mL)` `(µL)` `(단위: mL)`, 또는 기호 `℃` `㎖`)가 있으면, 그 근거 문장의 맨 숫자(단위 없는 칸)를 그 단위의 수치로도 친다. 그래서 `95°C` `20초`는 위 근거와 맞고, `5분`은 `(sec)` 아래 `300`과 맞는다. 같은 종류의 단위가 머리에 없으면 맞추지 않는다 (`(°C)`만 있는 표의 `300`은 `300초`의 근거가 아니다). `45회` `1단계`처럼 세는 말이 붙은 숫자, `tube(s)`처럼 영어 낱말에 붙은 괄호 속 한 글자는 맨 숫자·단위로 보지 않는다.
- 계산한 값(100 mL에 50 mL를 더해 150 mL)이면 원문과 맞는지 확인하고 둔다. 사용자가 준 값이면 `added`에 그 항목(`text`, `time`, `scene`)을 적는다 (그 항목은 대조하지 않는다).
- `check: "unsure"`인 단계는 이미 '원문 확인 필요'로 알렸으므로 대조하지 않는다.

**엄격 원문 검사**: `python scripts/check_data.py experiment.json --strict-source`. 원문 이름, 단계별 위치·근거 문장·판독 상태를 요구하고, 수치 불일치·판독 미확인·근거 누락을 오류로 처리한다. 앞 단계나 준비물에 같은 숫자가 있어도 현재 단계의 근거를 대신하지 않는다. 필요한 앞 문맥·준비물의 용량은 원문 그대로 해당 `quote`에도 포함한다. 부호와 전류·전압·저항·전력·진동수는 구별한다. 이 검사는 물질명이 뒤바뀐 오류나 근거 문장 자체의 오독을 판정하지 못하므로 원문 확인표로 물질·양·넣는 대상을 함께 맞춘다.

## 수업 기능

```json
{ "title": "지시약 떨어뜨리기", "observe": "색이 어떻게 변하는지 관찰해요.",
  "predict": "세 시험관의 색은 같을까요, 다를까요?",
  "reveal": { "text": "산성 용액은 붉은색, 염기성 용액은 초록색으로 변해요.",
              "remove": ["dropper"], "change": { "A": { "color": "red" }, "C": { "color": "green" } } },
  "scene": [ { "t": "rack", "x": 220, "tubes": [ { "id": "A", "fill": 0.4, "color": "clear" }, { "id": "B", "fill": 0.4, "color": "clear" }, { "id": "C", "fill": 0.4, "color": "clear" } ] },
             { "t": "dropper", "over": "A", "color": "purple" } ] }
```

- `predict`: 관찰 전에 예상을 적는 칸 (글자 하나 또는 배열). 원문에 예상·가설 물음이 있거나 사용자가 고른 것만.
- **고르는 예상**: `predict`에 글자 대신 `{ text, choices, answer, why, write }`를 주면 보기 중에서 고른다 (글자 예상과 섞어 배열로 줘도 된다). 아래 '고르는 예상'.
- `reveal`: '결과 보기'를 눌러야 보이는 결과. 글자만 주거나, 그 단계 장면에서 바뀐 결과 그림을 함께 준다 (`from` 없이 `remove`·`change`·`add`만 쓰면 그 단계 장면에서 바뀐다). 원문이 결과를 알려 줄 때만.
- `time`에 `"약 15분"`, `"30초"`, `"1분마다"`처럼 시간이 있으면 수업 모드에 타이머가 생긴다 (`"마다"`면 그 간격마다 소리). `timer`에 초를 숫자로 주면 그 시간으로, `false`면 끈다. 하룻밤·며칠처럼 수업 중에 재지 않는 시간은 `"timer": false` (검사기가 2시간이 넘는 타이머를 알려 준다).
- 결과 표의 빈칸(`""`), `questions`, `predict` 칸은 화면에서 바로 적는다 (그 기기의 브라우저에만 저장).
- 저장 상태를 화면에 표시한다. 저장이 막히거나 용량이 차면 닫기 전에 **답안 내보내기**로 글·그림 답안을 JSON에 보관한다. **답안 가져오기**는 같은 실험의 백업만 받으며, 기존 답안이 있으면 바꾸기 전에 확인한다. 인터넷 없이도 쓸 수 있다. `id`가 있는 자료는 다른 기기에서도 같은 자료를 열어 복원할 수 있다.
- 인쇄는 **학생용 학습지**(결과 그림·예상 결과·정리·메모·원문 대조를 빼고 적는 줄과 이름 칸)와 **교사용**(결과 그림·원문 대조까지)을 고른다.

### 고르는 예상

원문이 예상 물음에 보기(①·②, '같다/다르다', ○×)를 줄 때 쓴다. 학생이 보기를 고르기 전에는 **그 단계의 '결과 보기'가 잠기고**, 결과를 열면 고른 답이 굳는다. `answer`가 있으면 결과를 열 때 맞힌 예상에 **도장**이 찍히고, 결과 정리 위에 '예상 도장' 모음이 나온다.

```json
{ "title": "두 컵 식히기", "observe": "어느 컵이 먼저 식는지 관찰해요.",
  "predict": [ { "text": "어느 컵의 물이 먼저 식을까요?", "choices": ["가 컵", "나 컵", "같다"],
                 "answer": "가 컵", "why": "가 컵은 겉넓이가 넓어 열을 빨리 잃어요.", "write": "그렇게 생각한 까닭" } ],
  "reveal": { "text": "가 컵의 물이 먼저 식었어요." },
  "scene": [ { "t": "cup", "id": "a", "x": 180, "fill": 0.6, "label": "가 컵" }, { "t": "cup", "id": "b", "x": 300, "fill": 0.6, "label": "나 컵" } ] }
```

| 항목 | 뜻 |
|---|---|
| `text` | 예상 물음 (필수) |
| `choices` | 보기 2~6개 (원문 그대로) |
| `answer` | 정답 보기 (글자 하나, 여럿이면 배열). **원문(교사용 답 포함)이나 사용자가 알려 준 것만.** 모르면 빼면 도장 없이 "결과와 비교해 봐요"만 나온다. 사용자가 알려 준 정답은 `origin.added`에 `"answer"` |
| `why` | 결과를 연 뒤 보이는 까닭 (원문 근거가 있을 때만) |
| `write` | 고른 뒤 까닭을 적는 칸의 안내 글 (`"그렇게 생각한 까닭"`) |

- 고르는 예상은 결과(`reveal`)가 나오는 단계에 둔다. 그 단계에 `reveal`이 없고 `answer`나 `why`가 있으면 '정답 보기' 단추가 생긴다. 둘 다 없으면 확인할 곳이 없어 검사기가 알려 준다.
- 결과를 연 뒤에는 보기를 바꿀 수 없다. **적은 내용 지우기**를 하면 다시 고를 수 있다.
- 인쇄: 학생용에는 보기만(고른 것은 표시), 교사용에는 정답과 까닭이 함께 나온다.

## 결과 정리 (`results`)

| 항목 | 뜻 |
|---|---|
| `expect` | 예상 결과. 화면에서 접혀 있고 '결과 보기'로 연다 |
| `conclusion` | 원문의 결론·정리 글 (없으면 지어내지 않는다). '결과 보기'로 연다 |
| `table` / `tables` | 결과 표 `{ id, title, head, rows }`. 여러 개면 `tables` 배열. 빈칸 `""`은 적는 칸. 합친 칸·쓰지 않는 칸은 아래 '표 칸' |
| `questions` | 생각해 볼 질문. 글자, 또는 `{ "id": "q-acid", "text": "…" }` |
| `sketches` | 결과를 그리는 **그림 칸** 배열 (아래 '그림 칸') |


## 표 칸 (합친 칸·쓰지 않는 칸)

원문 표에 가로·세로로 합친 칸이나 빗금·회색으로 칠한(쓰지 않는) 칸이 있으면 칸을 객체로 쓴다. 글자 칸(`"위치(cm)"`)과 적는 칸(`""`)은 예전 그대로다.

| 칸 | 뜻 |
|---|---|
| `{ "text": "A 모둠", "rowspan": 3 }` | 아래로 3줄을 합친 칸. 아래 두 줄에서는 이 칸을 **빼고** 쓴다 |
| `{ "text": "구분", "span": 2 }` | 오른쪽으로 2칸을 합친 칸 (머리 칸에도 쓴다) |
| `{ "off": true }` | 쓰지 않는 칸 (빗금 회색, 적을 수 없음). `span`·`rowspan`과 함께 쓸 수 있다 |

```json
{ "id": "grow", "title": "모둠별 측정 기록",
  "head": [{ "text": "구분", "span": 2 }, "1회", "2회", "3회"],
  "rows": [
    [{ "text": "A 모둠", "rowspan": 2 }, "길이(cm)", "5", "", ""],
    ["무게(g)", { "off": true }, "", ""],
    [{ "text": "B 모둠", "rowspan": 1 }, "길이(cm)", "5", "", ""]
  ] }
```

- 줄마다 칸 수(합친 칸은 합친 만큼, 위에서 내려온 세로 합친 칸 포함)가 머리 줄과 같아야 한다. 검사기가 센다.
- 한 줄짜리 묶음 이름도 `"rowspan": 1`로 쓰면 다른 묶음과 같은 모양·같은 이름 규칙이 된다 (위 예의 'B 모둠').
- 적은 답은 '합친 줄 이름 + 줄 이름'과 머리 칸으로 저장된다 (위 예: `A 모둠 길이(cm)`의 `2회`). 합친 칸이 없는 표는 예전과 같은 이름이라 적은 답이 그대로 이어진다.

## 그림 칸 (`sketch`, `results.sketches`)

원문이 관찰한 모습·결과를 **그림으로 그리게 할 때** 쓴다. 화면에서 손가락·마우스·펜으로 그리고(색 4가지, '다시 그리기'), 그린 그림은 적은 답처럼 그 기기의 브라우저에 저장된다. 학생용·교사용 인쇄에는 칸 모양(그린 그림이 있으면 함께)이 나온다.

```json
{ "sketch": { "id": "cells", "title": "현미경으로 본 세포의 모습", "shape": "circle", "labels": ["증류수", "소금물"], "write": "배율" } }
```

| 항목 | 뜻 |
|---|---|
| `title` | 무엇을 그리는지 (원문 물음) |
| `shape` | `'circle'`(현미경 시야, 기본) · `'box'`(빈 네모) · `'polar'`(극좌표 원: 0°~315° 눈금, 궤적·방향 그리기) · `'spectrum'`(스펙트럼 띠: 위에 파장 눈금, `labels`의 칸마다 한 줄씩 쌓임) |
| `range` | `'spectrum'`의 파장 범위 `[400, 700]`(기본, nm). 원문 눈금대로 (`[300, 800]`) |
| `n`, `labels` | 칸 수(1~6)와 칸마다 이름 (`labels`만 주면 그 수만큼) |
| `write` | 칸마다 아래에 한 줄 적는 칸 (예 `"배율"`) |
| `note` | 칸 아래 안내 글 (원문에 있을 때) |
| `id` | 그린 그림이 저장되는 이름. 같은 제목의 그림 칸이 둘 이상이면 꼭 준다 |

- 단계에서 그리면 그 단계의 `sketch`(하나 또는 배열, 단계 카드에서는 장면·설명 아래에 카드 전체 너비로, 수업 모드에서는 설명 옆에), 결과 정리에서 그리면 `results.sketches`. 인쇄에는 `write`의 안내 글('배율 (   )배')이 적는 줄과 함께 남는다. 원문의 칸 수·이름을 그대로 따른다.
- 원문에 그리는 칸이 없으면 만들지 않는다 (원문에 없는 활동을 더하지 않는다).

## 설계 안내판 (설계형 활동)

원문이 과정을 학생에게 맡기는 활동(SKILL.md 0장 '설계형')에서 사용자가 ②를 고르면 만든다. 과정을 지어내지 않고 원문에 있는 것만 넣는다.

- `steps`: 원문의 설계 순서(가설 세우기 → 조건 정하기 → 과정 쓰기 …). 원문이 순서를 주지 않으면 원문 물음마다 한 단계.
- `scene`: 준비물을 늘어놓기만 한다 (`x`를 생략하면 고르게 놓인다). 붓기·가열 같은 동작은 그리지 않는다. `note`에는 원문 물음만 쓴다.
- 학생이 적는 곳: 원문의 가설 물음은 그 단계 `predict`, 설계 물음은 `results.questions`, 계획표는 빈칸 `""`이 있는 `results.table`.
- ①(선생님이 정한 과정)을 고르면 그 과정을 원문처럼 쓴다: `source`에 `"원문 이름 + 선생님 과정"`, 단계 `origin.where`에 `"선생님 과정 3"`, `quote`에 선생님이 준 문장.

```json
{
  "title": "설탕이 녹는 빠르기 실험 설계하기",
  "goal": "설탕이 녹는 빠르기에 영향을 주는 조건을 찾는 실험을 설계한다.",
  "materials": [
    { "name": "비커 (100 mL)", "qty": "3개", "icon": { "t": "beaker", "vol": "100 mL" } },
    { "name": "각설탕", "qty": "6개" },
    { "name": "초시계", "qty": "1개" }
  ],
  "steps": [
    {
      "title": "가설 세우기",
      "text": "설탕이 빨리 녹는 조건을 예상해 가설을 세운다.",
      "predict": "어떤 조건에서 설탕이 가장 빨리 녹을까요?",
      "origin": { "where": "탐구 설계 ①", "quote": "설탕이 빨리 녹는 조건을 예상해 가설을 세운다. 어떤 조건에서 설탕이 가장 빨리 녹을까?", "check": "ok" },
      "scene": [ { "t": "beaker", "vol": "100 mL" }, { "t": "beaker", "vol": "100 mL" }, { "t": "beaker", "vol": "100 mL" }, { "t": "stopwatch", "x": 410, "y": 70 } ]
    },
    {
      "title": "조건과 과정 정하기",
      "text": "다르게 할 조건과 같게 할 조건을 정하고 실험 과정을 쓴다.",
      "origin": { "where": "탐구 설계 ②", "quote": "다르게 할 조건과 같게 할 조건을 정하고 실험 과정을 쓴다.", "check": "ok" },
      "scene": { "from": "prev" }
    }
  ],
  "results": {
    "table": { "id": "plan", "title": "우리 모둠 실험 계획", "head": ["항목", "내용"], "rows": [["다르게 할 조건", ""], ["같게 할 조건", ""], ["실험 과정", ""]] },
    "questions": [{ "id": "q-measure", "text": "무엇을 재어 빠르기를 비교할까요?" }]
  },
  "source": "탐구 활동지"
}
```

## 학생 답이 저장되는 이름

학생이 적은 답은 HTML이 아니라 각 기기 브라우저에 **실험 제목**(또는 최상위 `id`)별로 저장되고, 칸마다 아래 이름을 쓴다. 순서가 아니라 내용으로 정하므로 **단계·질문을 끼워 넣거나 순서를 바꿔도 답이 따라간다.**

| 칸 | 저장 이름 | 글을 고쳐도 답을 이으려면 |
|---|---|---|
| 예상 칸 | 물음 글 | 단계에 `id` (`"id": "heat"`) |
| 고르는 예상 | 물음 글 (고른 보기, `:w` 까닭 칸, `:done` 결과를 열어 굳음) | 단계에 `id` |
| 질문 칸 | 물음 글 | 질문을 `{ "id": …, "text": … }`로 |
| 표 빈칸 | 표 제목 + 줄 첫 칸 + 머리 칸 | 표에 `id` |

- 같은 HTML을 다시 고칠 때 이미 있는 `id`는 바꾸지 않는다. 한 자료 안에서 `id`가 겹치면 검사기가 오류를 낸다.
- v1.8까지의 HTML에서 적은 답은 새 엔진으로 처음 열 때 자동으로 옮겨진다 (그때의 순서 기준).

## 장면 이어받기

앞 단계와 장치가 같고 일부만 바뀌면 `scene`을 배열 대신 객체로 쓴다.

```json
{ "title": "지시약 넣기",
  "scene": { "from": "prev", "remove": ["pour", "btb"],
             "change": { "b": { "color": "green", "label": null } },
             "add": [ { "t": "dropper", "over": "b", "color": "green" } ] } }
```

- `from`: 이어받을 단계 (HTML 단계 순서 번호 또는 `"prev"`). 기구는 위치(자동 배치한 `x`까지)·색·양을 그대로 가져온다.
- `remove`: `id` 또는 부품 이름(`"dropper"`면 스포이트 모두). `change`: `id`로 골라 속성을 바꾸고, 값이 `null`이면 그 속성을 지운다 (삼발이 위로 옮기기: `"on": "tr", "x": null`). `add`: 새 부품.
- **설명·동작 부품(`note`, `text`, `arrow`, `mark`, `eye`, `label` 부품, `view`, `zoom`, `pour`)은 이어받지 않는다.** 필요하면 `add`에 다시 쓴다. 기구에 붙은 `label` 속성은 기구와 함께 이어진다.
- **공·수레·스포이트·약숟가락·향 불씨·피펫·측정기 같은 동작 부품은 이어진다.** 이번 단계에 없어야 하면 `remove`로 빼고, 자리만 바뀌면 `change`로 옮긴다 (`"change": {"ball1": {"at": 0.8}}`). `add`로 같은 부품을 또 놓으면 둘이 그려진다 — 검사기가 알려 준다.
- 바꾸거나 뺄 부품에는 처음 장면에서 `id`를 붙여 둔다.

## 움직이는 시연

따로 쓸 것은 없다. **이어받은 장면**은 앞 장면에서, **결과 보기**(`reveal`의 `change`·`add`·`remove`)는 과정 장면에서 바뀌는 모습을 1~1.5초 동안 보여 준다.

- 같은 부품(이어받은 것)의 위치(`x` `y` `at` `dx` `dy`)·기울기(`tilt`)·크기(`s`)·액체 높이(`fill` `level`)·늘어남(`stretch`)이 서서히 바뀌고, 색(`color` `solidColor`)이 섞이며 바뀌고, 숫자 표시(`reading` `value` `amount`, 예: `'20 ℃'` → `'60 ℃'`)는 숫자를 세며 바뀐다. 켜고 끄기(`lit` 등)·가리키는 곳(`on` `over` …)은 가운데에서 바뀐다.
- 새로 놓인 부품은 나타나고(스포이트·피펫·약숟가락·온도계·붓기 같은 동작 부품은 위에서 내려온다), 빠진 부품은 흐려진다. 둘이 함께 있으면 그것을 먼저 하고 그다음 바뀐다.
- 수업 모드에서 **앞으로 넘길 때** 그 단계의 시연을 한 번, **결과 보기**를 누르면 결과 시연을 한 번 한다 (처음 열 때·뒤로 갈 때는 하지 않는다). 장면 오른쪽 위의 **▶ 시연**으로 다시 본다. 수업 모드에서 **3D**로 보는 중이면 시연도 입체로 한다 (액체 높이·색, 자리, 나타나고 사라지기. 숫자·그림이 바뀐 카드는 겹쳐 바뀐다).
- **움직임 끄기** 단추(머리 도구 줄·수업 모드 위쪽)는 방울·기포·김 같은 반복 움직임과 시연을 모두 멈추고 그 기기에 기억한다. 입체(3D) 보기의 움직임(방울·기포·김·불꽃·흔들기·젓기)도 함께 멈춘다. 기기의 '동작 줄이기' 설정이 켜져 있으면 처음부터 꺼져 있다.
- 같은 기구를 `add`로 새로 놓으면 사라졌다 나타나므로, 바뀌는 기구는 `id`로 `change`한다. 빠르게 움직이면 어색한 단계(하룻밤·며칠 뒤)는 `"motion": false`.
- 결과 시연은 결과 보기를 누른 뒤에만 한다 (고르는 예상이 있으면 예상을 고른 뒤).

## 부품 눌러 알아보기

따로 쓸 것은 없다. 수업 모드에서 장면의 부품(또는 그 이름표)을 누르거나 제목 아래 **부품 살펴보기** 목록에서 고르면 그 부품이 빛나고 **정보 카드**가 뜬다. 준비물 아이콘을 눌러도 같은 카드가 뜬다. 수업 모드에서 **3D**로 보는 중이면 입체 화면의 부품을 눌러도 같은 카드가 뜨고, 고른 부품은 보라색 틀로 둘러 보인다 (돌려도 틀이 따라간다. 같은 부품을 다시 누르면 닫힌다). 카드는 이 실험 자료에 있는 내용만 보여 준다.

| 카드 줄 | 어디서 |
|---|---|
| 이름 | 부품의 `label`(없으면 `text`, 꽂힌 시험관은 기구 이름 + `tag`)과 기구 이름, 용량 `vol` |
| 담긴 것·읽은 값 | 지금 보이는 장면의 `color`·`amount`·`fill`·`layers`·`solid`·`bubbles`·`steam`·`cloudy`·`gas`, `reading`·`value` (결과를 열었으면 결과 장면) |
| 준비물 | 이름표·글자가 든 준비물과 같은 기구의 준비물 (`icon`, 없으면 이름 짐작) |
| 설명 | 부품의 `info`, 준비물의 `info` |
| 이 기구는 (일반적인 사용법) | 엔진에 든 기구 기본 설명: 쓰임 · 다루는 법·읽는 법 · 주의 (자주 쓰는 기구 40종, 교사 검토를 거친 문장. 알코올 양·눈금 어림·가스버너 순서·전류계와 전압계 단자·pH 미터 보정은 여러 참고 자료가 함께 쓰는 기준). `info: false`면 숨긴다 |
| 이 실험의 안전 수칙 | `safety`와 그 단계 `warn` 중 이 부품의 이름표·기구 이름·준비물 이름이 든 문장 (원문 그대로) |

```json
{ "t": "beaker", "id": "b", "vol": "250 mL", "label": "가", "info": "실험지의 기구 설명 상자에 있던 문장" }
```

- `info`(글자 하나 또는 배열)는 **원문에 기구·물질 설명이 있거나 사용자가 준 것만** 쓴다. 지어내지 않는다. 사용자가 준 것이면 그 단계 `origin.added`에 `"info"`.
- 기본 설명이 원문의 안내와 어긋나면(예: 다른 사용 순서) 그 부품·준비물에 `"info": false`로 기본 설명을 끄고, 원문 안내는 그 단계의 `tip`·`warn`으로 넣는다.
- 말풍선·글자·화살표·이름표 부품·확대 원 같은 설명 부품은 누를 수 없다.

## 용량과 넣는 양

- 용량이 적힌 그릇(주사기·수조 포함)은 나오는 **모든 장면과 준비물 아이콘**에 `vol`을 준다. 수조는 크기를 바꾸지 않고 용량 글자만 새긴다. 용량·눈금이 새겨지고 **실제 부피 비율대로 크기가 정해진다**. 넣는 양은 `amount` (예: `"vol": "500 mL", "amount": "400 mL"`; 물은 1 g ≈ 1 mL). 붓는 쪽 그릇은 `pour`의 `fromVol`.
- 원문 글자 그대로 쓴다: `"1,000 mL"`, `"0.5 L"`, `"30~40 mL"`(가운데 값으로 그린다), `"0.5~1 L"`, `"500 μL"`, `"10 cc"`, `"1 dL"`. 그릇에는 원문 글자 그대로 새긴다.
- `g` 같은 부피가 아닌 단위, 읽지 못하는 값, 넣은 양 > 용량은 검사에서 오류가 난다.
- `vol`을 준 그릇에는 `s`를 주지 않는다. 꼭 키우거나 줄여야 하면 그 장면의 그릇들에 **똑같은** `s`를 준다.
- 용량이 적혀 있지 않으면 `vol`을 지어내지 않는다.
